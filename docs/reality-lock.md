# Reality Lock

Spec can be funny, but the system cannot be fake.

Mirror Mode, checkpoints, moods, and reward updates must be grounded in measured interaction data:

- cursor position and dwell time
- click timing and repeated clicks
- typing, backspace, delete, and revision patterns
- hesitation before action
- app/window switching
- replay retry and failure events
- user accept, override, hesitation, and correction feedback
- real screenshot/VLM state when available
- actual recorded or saved workflows

Synthetic demo data is allowed only as a dev fallback. It must be labeled `synthetic demo data`, must never become the main Mirror Mode path, and must never be presented as learned behavior.

Pitch language should say measured, not magic:

- Spec is funny because your behavior is funny.
- The ghost's mood is a real-time visualization of behavioral signals.
- Mirror Mode is replay plus persona-conditioned execution from measured interaction data.
